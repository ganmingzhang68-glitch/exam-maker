# 数据库索引与 N+1 审计（Phase 11）

迁移 025 针对实际高频条件增加复合索引：考试/学生/状态作答、作答答案批改状态、学生任务截止时间、课程题目生命周期、考试题目质量审核、AI 调用状态/模型/时间、后台任务状态/时间、项目事件时间。没有为所有单字段无差别建索引。

前端答案输入已使用 800ms debounce，切换后的保存由每题 timer 执行，手动保存与提交前会 flush 全部答案；自动保存 API 未加入限流。

检查结果：考试成绩和题目质量仍含少量逐项组装查询；知识点课程分析会按学生重新同步，班级很大时是最明显的 N+1 风险。Phase 11 先用索引和 100 并发基线保证正确性，没有在缺少真实生产规模数据时大改统计架构。后续应把知识点证据计算迁到提交/批改事件并按课程批量聚合。
